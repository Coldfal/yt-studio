# Testing

Pytest conventions, fixtures, mocking patterns, and how to add a new
test without fighting async SQLAlchemy.

## Quick start

```powershell
cd backend
.\venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt   # one-time
pytest -v
```

108 tests passing, 2 skipped (the skips are runtime-only path checks
that don't fire in the test fixture). Suite runs in ~4 seconds on a
typical laptop — fast enough to run on every save.

To run a single file or a single test:

```powershell
pytest tests/test_video_project_tracks.py -v
pytest tests/test_youtube_service.py::test_upload_applies_localizations_via_update -v
```

## What's covered, what isn't

### Covered

- **Worker pools** — semaphore admission control per task type.
- **Task runner** — handler-by-handler smoke tests (compose, upload,
  metadata, music, image, automation_run) with mocked external APIs.
- **Automation service** — quick_generate happy path, image
  selection, track selection, num_tracks override, visualizer-disabled
  flag.
- **Compose service** — `_build_filename`, `extend_video` snap-to-song
  math.
- **Credentials service** — Fernet round-trip, decrypt-failure handling.
- **Exceptions** — every AppError subclass + the FastAPI handler.
- **Rate limiter** — token-bucket math, per-channel keying.
- **Retention worker** — old-task cleanup, orphan-file detection.
- **Stats endpoint** — per-channel aggregations.
- **Storage endpoint** — disk-usage breakdown.
- **m2m tracks** — VideoProjectTrack model, CASCADE behavior, JSON
  fallback.
- **YouTube service** — localizations applied via follow-up
  `videos.update` after `videos.insert`.
- **Asset reassign** — channel reassignment + folder unlink.
- **Overlay assets** — corner overlays in the visualizer config.
- **Metadata post-processing** — title sanitization, tag dedup,
  description tracklist insertion.

### Not covered (manual / smoke-only today)

- **Frontend** — no automated tests yet. Manual smoke testing in
  the browser preview is the workflow.
- **Visualizer engine** — Node sidecar output is verified by eye,
  not byte-by-byte.
- **Live streaming** — `streaming_service.py` has no unit tests
  (deferred until split — see `memory/backlog.md`).
- **End-to-end OAuth** — test fixtures mock the YouTube client, not
  Google's actual auth flow.

async def test_set_project_tracks_replaces_on_second_call(db, channel):

blank lines.

## Fixtures

All defined in `tests/conftest.py`. Mostly auto-generated by pytest
based on argument names; you don't import them.

### `db`

A fresh `AsyncSession` per test. Backed by an **in-memory SQLite**
database (no `data/studio.db` involvement). The schema is built
once per session, rows are wiped between tests.

```python
async def test_something(db):
    db.add(VideoProject(channel_id=1, title="x"))
    await db.commit()
```

The fixture is scoped to a function — no leakage between tests.

### `channel`

A pre-built `Channel` row. Use when you don't care about the
channel's specifics; the fixture saves you a few `db.add(...)`
lines:

```python
async def test_create_project(db, channel):
    p = VideoProject(channel_id=channel.id, title="t")
    db.add(p)
    await db.commit()
    assert p.id is not None
```

### `preset`

A pre-built `AutomationPreset` wired to `channel`.

### `music_assets`

Three `Asset` rows of type `music`, channel-scoped to `channel`.
Returned as a `list[Asset]` so you can index by position:

```python
async def test_select_tracks(db, channel, music_assets):
    ids = [a.id for a in music_assets]
    ...
```

### `image_assets`

Two image `Asset` rows for `channel`.

### `video_project`

A draft `VideoProject` for `channel`.

### `background_task`

A pending `BackgroundTask` linked to `channel`.

### `patched_services`

Mocks every external integration (FFmpeg, YouTube, Claude, Suno,
DALL·E) to return safe stubs. Returns a dict so individual tests
can override the default:

```python
async def test_compose(patched_services, db, channel):
    # default mock returns a fake MP4 result
    result = await compose_service.compose_video(...)
    assert result["filename"] == "out.mp4"

    # override for a specific test
    patched_services["compose"].return_value = {
        "filename": "custom.mp4", ...
    }
```

Mocks live in `services/<name>_service.py` modules — see
`patched_services` in `conftest.py` for the canonical patch points.

## Adding a new test

### 1. New file?

Yes if you're testing a new service. Conventionally
`tests/test_<service>.py`.

### 2. Imports

```python
from __future__ import annotations
import pytest
from sqlalchemy import select

from app.models import Asset, VideoProject
from app.services.your_service import your_service
```

### 3. Function signature

```python
@pytest.mark.asyncio
async def test_your_thing_happens(db, channel):
    ...
```

`@pytest.mark.asyncio` is **required** — the marker tells
pytest-asyncio to run the function in an event loop. Forgetting
it gets you "coroutine never awaited" warnings + skipped tests.

(pytest.ini has `asyncio_mode = auto` so async tests get the marker
implicitly. If you see warnings, double-check the file.)

### 4. Arrange

Build whatever DB state the test needs. The fixtures cover the
common cases; for one-off rows, just `db.add(...)` them:

```python
project = VideoProject(channel_id=channel.id, title="x")
db.add(project)
await db.flush()           # use flush to get the id without committing
```

`flush()` issues the INSERT but stays in the transaction, so the
test cleanup can roll back. `commit()` works too in tests because
the auto-truncate fixture wipes everything between tests anyway.

### 5. Act

Call the service or helper:

```python
result = await your_service.do_thing(db, project_id=project.id)
```

For async iteration, use the standard pattern:

```python
rows = (
    await db.execute(
        select(VideoProjectTrack)
        .where(VideoProjectTrack.project_id == project.id)
        .order_by(VideoProjectTrack.position)
    )
).scalars().all()
```

### 6. Assert

```python
assert result.something == "expected"
assert len(rows) == 3
assert [r.asset_id for r in rows] == [a.id for a in music_assets]
```

Plain `assert` — no `unittest.TestCase` machinery. Pytest's
introspection makes failures readable.

## Mocking patterns

### Mocking a service method

```python
async def test_uploads_with_localizations(patched_services, db, channel):
    upload = patched_services["youtube_upload"]
    upload.return_value = {"video_id": "abc", "url": "..."}

    # call code that calls youtube_service.upload_video
    ...

    upload.assert_called_once()
    args = upload.call_args.kwargs
    assert "localizations" in args
```

### Mocking a brand-new external dependency

If your service uses something not already in `patched_services`,
add it. Edit `conftest.py` `patched_services` fixture:

```python
foo_call = AsyncMock(return_value={"ok": True})
mocker.patch("app.services.foo_service.foo_service.do_thing", new=foo_call)
return {..., "foo": foo_call}
```

Now every test that asks for `patched_services` gets the foo mock
too.

### Mocking a sync function called from async code

`MagicMock` (sync) — not `AsyncMock`. Easy to mix up:

```python
patcher = mocker.patch("app.utils.crypto.encrypt", return_value=b"ciphertext")
```

If you accidentally use `AsyncMock` for a sync function, the
production code gets a coroutine back where it expected bytes and
fails confusingly.

### Mocking `googleapiclient` (YouTube API)

See `tests/test_youtube_service.py`. The pattern:

```python
def _make_youtube_mock(video_id="vid123") -> MagicMock:
    yt = MagicMock()
    insert_req = MagicMock()
    insert_req.next_chunk.return_value = (None, {"id": video_id})
    yt.videos.return_value.insert.return_value = insert_req
    yt.videos.return_value.update.return_value.execute.return_value = {}
    return yt

with patch("app.services.youtube_service.build", return_value=yt_mock), \
     patch("app.services.youtube_service.MediaFileUpload", return_value=MagicMock()), \
     patch("app.services.rate_limiter.rate_limiter.acquire", return_value=None):
    result = await svc.upload_video(...)

# Verify the right calls
yt_mock.videos.return_value.update.assert_called_once()
```

Don't try to use the real `googleapiclient` in tests — it'll try to
hit Google for credential exchange even with mock OAuth tokens.

## CASCADE / database invariant tests

Pattern when verifying CASCADE behavior:

```python
async def test_cascade_delete_project_removes_tracks(db, channel):
    # Arrange: create + commit so FK relationships are real
    asset = await _make_asset(db, channel.id)
    project = await _make_project(db, channel.id)
    await set_project_tracks(db, project.id, [asset.id])
    await db.commit()

    # Act: delete the parent
    project_id = project.id
    await db.delete(project)
    await db.commit()

    # Assert: child rows are gone
    remaining = (
        await db.execute(
            select(VideoProjectTrack).where(
                VideoProjectTrack.project_id == project_id
            )
        )
    ).scalars().all()
    assert remaining == []
```

The `await db.commit()` between Arrange and Act is critical — the
SQLAlchemy session won't actually fire the CASCADE until the
transaction commits.

## Testing async time-sensitive code

The rate limiter and retention worker have time-based logic. Use
`freezegun` or `unittest.mock.patch("datetime.utcnow")`:

```python
from unittest.mock import patch
from datetime import datetime, timezone

@patch("app.services.rate_limiter.datetime")
async def test_bucket_refills(mock_dt, ...):
    mock_dt.now.return_value = datetime(2026, 5, 5, tzinfo=timezone.utc)
    # bucket starts here

    mock_dt.now.return_value = datetime(2026, 5, 5, second=60, tzinfo=timezone.utc)
    # bucket has refilled by 1 token
```

Keep these tests focused — one timing scenario per test, named
explicitly (`test_bucket_refills_after_60_seconds`).

## What the test suite catches

The 108 tests aren't comprehensive coverage — they're a tripwire
for:

- A handler swallowing a credential error silently.
- Schema migrations that don't honor existing data.
- A service refactor that changes behavior subtly (e.g. dropping a
  CASCADE, changing track-selection randomness).
- Endpoint contracts (JSON shapes) drifting from what the frontend
  expects.

If a refactor passes the suite, the externally-observable behavior
is the same. That's the bar.

## Running tests in CI / pre-commit

Not set up yet. The `pytest -v` command takes ~4 seconds, so a
pre-commit hook is feasible. If you set one up:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: local
    hooks:
      - id: pytest-backend
        name: pytest backend
        entry: bash -c 'cd backend && pytest -q'
        language: system
        pass_filenames: false
        files: '^backend/'
```

For full CI, GitHub Actions with a matrix on Python 3.11 / 3.13
would catch version-specific issues. Currently not wired.
